OBS で 3D の絵を受ける

スキャンの上にドローンの位置と軌跡を描いた 3D の絵を、この機械（会場のネットワークでは rt4090）が NDI と SRT で送っている。受け方は 3 つ。下の URL の IP は、このページを開いたときの機械の住所で埋めてある。会場のネットワークが変わったら、このページを開き直す。

1. NDI（おすすめ）

Windows の OBS に NDI のプラグイン（DistroAV）と、NDI Runtime（DistroAV が入れるよう求める）が入っていること。

  1. ソースの「＋」→「NDI™ Source」
  2. Source name で … (ghostline 3D) を選ぶ
  3. Bandwidth は Highest、Latency mode は Low

遅れは数フレーム。同じネットワークの何台からでも同時に受けられる。一覧に出ないとき（ネットワークが分かれている、Windows のファイアウォール）：NDI Access Manager →「Remote Sources」に rt4090 を足して OBS を開き直す。初回に Windows が OBS の通信を許可するか聞いてきたら「許可」。

2. SRT（プラグイン不要）

  1. ソースの「＋」→「メディアソース」
  2. 「ローカルファイル」のチェックを外す
  3. 下の表のとおりに入れる
入力srt://rt4090:9000?mode=caller&latency=120000
入力形式mpegts
ネットワークのバッファリング0 MB
再接続の遅延1〜2 秒
ハードウェアデコードオン（Windows でも同じ）
FFmpeg Optionsfflags=nobuffer analyzeduration=1000000 probesize=1000000

遅れは OBS の中で 3〜4 秒（既定のままだと 6〜10 秒）。つなげるのは 1 台だけ。latency はマイクロ秒で、120000 は 120 ms。

3. ブラウザソース（転送なし）

URLhttp://rt4090:8080/view/?ndi=1&fps=30
幅 × 高さ1920 × 1080

描くのは OBS の PC の GPU。遅れはいちばん小さいが、OBS の PC が重くなる。設定 → 詳細設定で「ブラウザソースのハードウェアアクセラレーション」をオンにしておく。

知っておくこと

  • カメラは操作ページで切り替える：「配信のカメラ」の 全体・真上・マスの名前（その人を追いかける）とズーム。押すとすぐ OBS の絵が変わる（約 0.5 秒）。
  • 受け手がいないあいだは描いていない（電池のため）。つないでから約 1 秒で動き出し、最初の 1 秒は前の絵が出る。OBS のソースを非表示にしても受け続けるなら描き続ける。
  • 大きさと fpsは操作ページの「配信」で選ぶ（既定 1280×720・30 fps）。変えると送り手が 2〜3 秒止まって立ち上げ直すので、ヒートの合間に。
  • 絵が出ないとき：操作ページの「配信」が「止める」になっていないか。NDI なら送り手の名前が一覧に出るか（同じネットワークか）。SRT なら別の PC が先につないでいないか。
