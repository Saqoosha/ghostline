# UDGP 2026 R3（屋内の倉庫、2 階建てのコース）

会場の Insta360 の 360 動画だけでスキャンと地図を作り、ZowieBox の 2×2 の録画から HDZero の全 65 本の走りを、ライブ用の tracker
（`rt_track.py`、`RENDER=1`）をオフラインで前向きと逆向きに流して位置合わせした。アナログの 27 本も同じ形で追えた。全 92 本の飛んでいる区間で解けた割合は中央値 93.6%。
観客向けのページは https://ghostline.saqoo.sh/udgp-2026-r3/ （試しは `staging-udgp-2026-r3`）。

## 素材

| 素材 | 中身 |
|---|---|
| Insta360 の歩き撮り | dual-fisheye の `.insv`。spirula で SfM（IMU の縮尺、z が上、床が z=0）と 3DGS |
| EventVRX（ZowieBox） | 1920×1080 の 2×2、59.94 fps、HEVC 約 40 Mbps。1 マス 960×540 に HDZero の 4:3 が引き伸ばされ、下 18 行が黒（絵は上 522 行）。マス n は (n%2·960, n//2·540) |
| RotorHazard | ヒート・選手のノード・ラップ。ZowieBox のファイル名の時刻と RH の時計は 1 秒未満で一致 |

選手の映像方式：HDZero はカロヤン・shuntana・くっすー・シャーマツナブル・yashiko・KPro-FPV・K-house・a2c。ReinaStyle❤FPV は両方（Heat 17 はアナログ）。
アナログは Rookie2.1・フォレスト森澤・ゆっきーFPV・Saqoosha（4 人で 27 本）。アナログも HDZero のカメラの定義（stock / upgrade）のまま追える（Saqoosha の 60 秒で upgrade 94.5%、stock を 10% 広げると 86%、20% で 69%）。

## 通し

1. **スキャン**：spirula の `sam extract`（人を消すマスク）→ `sfm auto`（`--rig dual-fisheye`、`--telemetry` で縮尺）→ `train 360-camera`（6M splat、30k、`--floater-suppression mild`）。
   ROI（`<dataset>/roi/*.json`）を置くと学習が自動で読む。今回は建物の L 字の箱から南東を引いた形
2. **SIFT の地図**：`tools/mgp/map_from_360.py` が spirula の姿勢を固定のまま、魚眼 1 枚を 5 方向のピンホールに切って三角測量する。キーフレームの候補と、最初の位置合わせ（SIFT、2〜4 割しか解けない）に使う
3. **キーフレームの地図**：`tools/dvr/udgp_kf_poses.py` で SIFT の答え（インライア 40 以上、4.7 万）と 360 のカメラ（9,430）を候補にし、`rt_map.py` で 5,309 枚（約 4 分、4090）
4. **追跡**（1 本ずつ）：`udgp_pinhole.py` が原本から 1 マスを 60 fps のピンホール動画に（x264 crf 8）→ `udgp_reverse.sh` で逆向き →
   `rt_track.py`（`LIVE=0 RENDER=1 RCLIP=2 SCENE=<スキャンの .ply>`）を両方向に → `udgp_merge_track.py`（両方解いたフレームはインライアの多いほう）
5. **ページ**：`TRACK=<答えのフォルダ> tools/dvr/udgp_heats.py` が night_heats の `cut_heat` でヒートごとの race.json とクリップを作る。`tools/dvr/udgp_official.py <RH の .db> <heats-*.jsonl> <出力>` が RotorHazard のラップを race.json の `official`（最初の通過がホールショット）に、heats.json に `closed` と `sessions` を足す。一覧（heats.json）は publish-event.sh が空でしか置かないので別に上げる

全 65 本は Vast.ai の 4090×8 で回した（`tools/vast/`：`udgp_setup.sh` が環境、`udgp_push_src.sh` が Studio から原本を 6 本並べて送り、`udgp_queue.py` が 1 枚の GPU に 2 本ずつ流す。1 本は両方向とレンズの試しで約 53 分、全体で約 4 時間、約 25 ドル）。

## 基準値

| 段階（a2c の Heat 17、レースの間） | 解けた割合 |
|---|---|
| SIFT（画質を落とした録画、30 fps） | 28% |
| tracker、キーフレームで照合（原本、60 fps） | 76% |
| ＋`RENDER=1` | 92.6%（1.5 秒を超える穴 4） |
| ＋逆向きも追って合わせる | 97.0%（最長の穴 0.45 秒） |

- 前向きと逆向きが両方解いたフレームの位置の差：中央値 6〜8 cm、90% で 0.24〜0.30 m
- 全 92 本、飛んでいる区間：中央値 93.6%。選手ごとの中央値は Saqoosha（アナログ）99.0%、KPro-FPV 97.4%、yashiko 96.8% から、ゆっきーFPV 76.8%、シャーマツナブル 76.3%、Rookie2.1 71.4%（アナログの受信が悪い）まで。低い走りは墜落（FAILSAFE で裏返る絵）か受信の悪さ
- 速さ：4090 を WovenCity の学習と分け合って 1 フレーム 43〜54 ms、Vast の 4090 に tracker 4 つで 52 ms
- レンズの試し（60 秒）は、ほとんどの走りで 3,000〜3,550 / 3,596 フレーム。stock と upgrade の差は 1 割前後
- 残る穴は毎周同じ場所：2 階（6〜7.5 m）から 1 階へ降りる区間。逆向きに追うとその先から入れるので埋まる

## 観客向けのページ（屋内）

index.json に足す値（`viewer/src/aud/stage.ts`、`viewer/src/occlude.ts`）：

| 値 | 意味 |
|---|---|
| `room.polygon` | 床の形（x, z の角、凹んでもよい）を `margin` だけ内側に寄せた柱。外にあってカメラと柱のあいだに立つ splat（手前の壁と屋根）を消す。UDGP は L 字の 9 角、margin 1.5 m |
| `cut` | 高さで切る。見えている選手が全員 `cut[0] − 0.3` より下なら `cut[0]`（2 階の床、3.6 m）、そうでなければ次の値（屋根、8.3 m） |
| `orbitPitch` / `orbitMin` | ORBIT の俯角（−55°）と最短距離（20 m）。屋内では既定の −18° と 12 m だと部屋の中に入る |

`?still&t=<秒>&yaw=<度>&pitch=<度>` で角度と時刻を決めて撮れる（合成したドラッグでは向きが変わらなかった）。
カメラから一定距離より手前を全部切る方法も試したが、2 階の床の手前まで消えて見づらく、やめた。

## ハマりどころ

- **ヒートの切り出しで画質を落とすと、位置合わせが大きく落ちる。** 最初に `hevc_videotoolbox -b:v 4M`（実際 5.4 Mbps）で切った録画から SIFT を回していた。原本（約 40 Mbps）と比べると HDZero の乱れのまわりがブロックににじみ、特徴点の拾う輪郭が消える。追跡の入力は原本から直接取る（`udgp_pinhole.py`）。ページのクリップ（H.264、960×540、30 fps、約 1.8 Mbps）はその録画から切ったままだが、ページでは小さく出るので足りる
- **オフラインの tracker は全フレームを最初にメモリへ読む**（640×480 で 20,180 枚、18 GB）。16 本同時で 251 GB の機械が足りなくなった。`FRAME_JPEG=1` で JPEG にして持つ
- **ssh の向こうで `pkill -f <名前>` を打つと、その命令文を含む自分のシェルまで殺して、何も止まらない。** `pkill -f "[r]t_track.py"` のように括弧で書く
- **Vast で gsplat をその場でビルドするには ninja が PATH に要る**（venv の bin を PATH に入れる）。tracker は tqdm も要る。何本も同時に起動すると、ビルド済みの `gsplat_cuda.so` の読み込みと書き直しがぶつかり、`file too short` で落ちる走りが出る（流し直せば通る）
- **Vast の機械が `offline` のまま起動しないことがある。** 返して別の機械を借りる。`vastai destroy` は確認を求めるので `echo y |` で渡す。`create instance` の出力には鍵が入るので番号だけ取り出す
- **spirula の GUI は Finder 経由でフォルダを開けない**（「folder 形式は開けない」）。`spirula <folder>` で渡す。学習のフォルダは COLMAP の形（`images/`・`masks/`・`sparse/0`）にリンクでまとめる
- **ROI の JSON は手でも書ける**：`{"type": "box", "center": [...], "half": [...]}`。エディタは学習画面の Dataset の段（保存済みの領域があるとき）の Edit Region。`--roi-region` を省くと `roi/` の最初のファイルを黙って使う
- **`publish-event.sh` は 1 回にモードを 1 つしか受けない。** `<event> <シーン> <題> --night <heats>` と並べると `--night` は黙って捨てられ、ヒートのページが 404 になる。シーンと `--night` は別々に流し、ヒートの `race.json` が 200 で返ることまで確かめる
- **映像が長く止まった走りは「飛んでいる区間」の割合を下げる**：墜落して裏返った絵で誤った位置が出ると、動いていると数える。割合が低い走りは DVR を見てから判断する
